# Raw clang-repl against cpp-repl

clang-repl is LLVM's C++ REPL: a real JIT with a prompt, which cpp-repl drives
from a Python front end. This document types one session into both and shows
what each answers, measures what each costs to start and per input, and says
what raw clang-repl offers that cpp-repl does not. Every table here is
generated by [`compare.py`](compare.py) from the JSON in
[`results/`](results/); nothing in them is typed in by hand. The README's
[Why a front end](../README.md#why-a-front-end) holds nineteen probes of raw
clang-repl's known problems per version; they are not repeated here.

Raw clang-repl is the binary as apt.llvm.org ships it (23 and the
development snapshot). cpp-repl is this checkout, driving

## How both sides were fed

**Raw**, over a pipe, one line at a time, as a person typing at its prompt
does. After each input a `%lib` of a path that cannot exist marks where the
input's output ends; that is cpp-repl's own marker, and the error line it earns
is the same on every version. Raw clang-repl's first input declares `prctl`
and turns core dumps off, as cpp-repl's prologue does (a crash would
otherwise leave a crash report behind); nothing else is sent first. It
compiles as `gnu++26`, cpp-repl's default for a clang from 17 on. An input
raw clang-repl does not answer within twenty seconds is a hang: the process
is killed. A crash ends the process. Either way a fresh clang-repl replays
the inputs that had worked, so that the rows after it still have a raw
answer; those rows say so.

Two things about raw clang-repl's output over a pipe shape the table. Its
stdout is buffered, as any program's is on a pipe: a `std::cout` line shows
when `std::endl` flushes it, so the session's own lines end in `std::endl`
(cpp-repl's prologue unbuffers stdout, and every write comes back as it is
made). And the value of a bare expression (`x + 1`) comes through a buffer of
clang-repl's own, which flushes at exit: the rows say "nothing yet", and the
last row shows what came out with `%quit`. A `setvbuf(stdout, nullptr,
_IONBF, 0)` sent first, as cpp-repl's prologue sends it, would not do: it
made raw clang-repl lose every `std::cout` write that no `std::endl` flushed,
on 23 and 24 alike, so the generator sends none.

**cpp-repl**, through its own session, one input at a time, as the prompt runs
it (`Session.run_inputs` with `batch` off): a crash or an exception is
survived, as it is at the prompt, where a `--batch` run would stop as the
compiled program would. Full diagnostics, no profile, no project file. Its
column shows the output, then cpp-repl's own notes in brackets, then the
input's status when it is not `ok`.

Three rows cost raw clang-repl its session on every version: the `for` whose
first line ends in an open brace, which it never finishes (every input after
it is an error until the error limit, then it hangs); the uncaught exception,
which terminates the process; and the write through a null pointer, which
kills it. On 23.1.4 and 24 a fourth does: `return 3;` at top level segfaults
them, where cpp-repl ends the program with 3 as
`main()` would. After each, raw clang-repl knows nothing it was told: the
rows marked as a fresh process have their earlier inputs replayed by the
generator, which a person would have to type again. Of the two lambda
statements, the one passed to `std::for_each` ran on every version; the one
called on the spot crashed 23.1.4, as the README's probes say, where
24 ran it, the crash being fixed on main.

The rows for a bare value (`x + 1`, `v`, `ages`, `p`) show raw clang-repl's
value printing in the last row: a built-in prints with its type, `(int) 43`;
a class value prints its type and address on 23 and 24 (`(std::vector<int,
std::allocator<int> > &) @0x…`, the same before and after the `operator<<`
for `P` was typed). cpp-repl prints
the value in its row, and finds an `operator<<` typed after the first print.
Its `%undo` replays the session without the last input; raw clang-repl's
undoes it in place. The last row's exit status is 0 on 23 and 24 whatever
failed.

## What each can do

| | raw clang-repl 23.1.4 | cpp-repl |
| --- | --- | --- |
| **Input** | | |
| a block over several lines | an error per line; a line ending in `{` hangs it (killed after 20 s) | finished when its brackets balance and its statement is complete; a multi-line `if` waits for its `else`, a function head for its body |
| a pasted block of `#include`s and code | line by line, each on its own | one input; a trailing bare expression prints |
| completion, history, highlighting | libedit's line editing | Tab from every header the preludes include and the session's names, Ctrl-R search, C++ highlighting (prompt_toolkit) |
| **Printing a bare expression** | | |
| a built-in | `(int) 43` | `43` |
| a class value | `(std::vector<int, std::allocator<int> > &) @0x…` | `[3, 1, 2]`; maps, tuples, optionals, variants, smart pointers, wide strings, enums |
| a temporary of class type | a link error (`_ZNSaIiED1Ev`) | printed while it lives |
| a type of your own | its type and address | through its `operator<<`, even one typed after the first print, or `<T>` and a note saying how |
| a bare call of a void function | not run | run |
| **When things go wrong** | | |
| a segfault | the process is gone, with everything typed | `[clang-repl crashed (SIGSEGV): restored N inputs]`: the journal is replayed into a spare already running |
| an uncaught exception | `terminate called…`, the process is gone | `[uncaught exception: std::invalid_argument: stoi]`, the session goes on; `--batch` exits 134 |
| a link failure | later inputs may fail too | the session is restored, and an input that failed for an earlier error's stale template runs again |
| Ctrl-C | ends the process | stops the input, rebuilds the session without it |
| an input that never ends | runs forever | `--timeout SECONDS` stops it and rebuilds the session |
| declaring a name again | `error: redefinition of 'x'` (`%undo` first) | the session is rebuilt without the old declaration, `[x redefined: N inputs replayed]` |
| a crash report | Ubuntu's apport writes one (about 95 MB) unless core dumps are off | core dumps off before any library loads |
| **Diagnostics** | | |
| an error | clang's full text, named `input_line_N` or `<<< inputs >>>` | named by the file, line and column the input came from; brief under `--batch` (the first error, carets only in your code, three missing symbols demangled), full at the prompt |
| the exit status of a run | 0 whatever failed | the program's: `main`'s return, `exit(N)`, 128 + the signal; else 130, 124, 1 or 0 (README) |
| **Programs** | | |
| a `.cpp` file | `#include`-able only as a header | `main()` runs one statement at a time, after the rest of the file; `argc` and `argv` stand-ins; `return` ends it with its status |
| a session back out | — | `%save-cpp`: a program that builds with the session's flags |
| the program's own stdin | the same pipe its inputs come from | cpp-repl's stdin (`cpp-repl --batch prog.cpp < input.txt`) |
| **An agent's loop** | | |
| a batch run | pipe lines in; parse stderr yourself | `--batch`, `-q`, `--json` (a record per input: status, output, notes, seconds), `--stop-on-error`, `--timeout` |
| a session that stays | — | `--serve SOCKET` and `--connect`, a run in 0.07 s; `--fresh` for a clean one in the spare |
| **Configuration** | | |
| compiler flags | `--Xcc=FLAG`, any flag | the flags clang takes (`-I -D -O -std -stdlib -include -f -W -m` and more), `compile_commands.json` (response files read), `cpp-repl.toml`, profiles for Eigen, glm, libtorch and OpenUSD, `-l NAME`/`-L DIR`/`--lib` |
| the standard | C++ 17 unless told | the newest the clang knows (gnu++26 from clang 17); C++20 is the floor |
| the newest clang-repl | install it | Docker images with 23 and the snapshot; `--docker` mounts your directories at their own paths |
| **Timing and speed** | | |
| timing an input | — | `%time` (wall, and how long the code ran apart from compiling), `%timeit` as IPython's |
| optimisation | `--Xcc=-O3 --Xcc=-march=native` | `-O3 --native`; the same JIT, so the same speed (the [bench](../bench/README.md): 64 GFLOP/s either way) |
| **Meta commands** | `%help` (23 and 24), `%undo`, `%lib`, `%quit` | those, and `%restart`, `%reset`, `%journal`, `%save`, `%save-cpp`, `%load`, `%time`, `%timeit`, `%flags` |
| **Platform** | wherever LLVM builds; no dependencies; out-of-process execution (`--oop-executor`, 23 and 24); CUDA (`--cuda`, hidden) | Linux, Python 3.11 or newer, a clang-repl or Docker; a wheel from a GitHub release |

## What raw clang-repl has that cpp-repl lacks or costs

- **Nothing between you and clang.** It starts in a few hundredths of a
  second and answers an input in a millisecond or two; cpp-repl loads a
  precompiled header of its preludes, which the first start of a
  configuration builds in a few seconds (the table below), and a bare
  expression or a statement costs the compile of the small function it runs
  in.
- **No Python.** clang-repl runs wherever LLVM does.
- **`%undo` undoes.** It drops the last input's effects without running
  anything again. cpp-repl's `%undo` replays the journal without the last
  input, side effects included: a file written is written again.
- **Out-of-process execution** (`--oop-executor`, `--oop-executor-connect`,
  `--orc-runtime`, on 23 and 24) and the hidden CUDA options. cpp-repl passes
  compiler flags only, through `--Xcc`, and none of clang-repl's own.
- **Exactly upstream's behaviour and messages.** cpp-repl rewrites what it
  sends: control flow, lambda statements and expression statements run inside
  a function of their own, so a variable declared inside such a statement is
  a local of it; variables typed at the prompt are globals (a name can clash
  with a C library function's); a rebuild replays side effects; and a lexer
  decides what is a declaration and what is an expression, a decision the
  review that preceded this document found wrong for a bare `v[0]`, `f(*p)`,
  `n * v[i]` and `int w` (fixed), and that still prefers a declaration for an
  ambiguous `Foo *p;`.
- **A value prints with its type**, `(double) 7.0`, where cpp-repl prints
  `7`.
- **The program's stderr stays apart from its stdout**; cpp-repl merges them
  in a `--batch` run and in `--json`'s `output`.
- **`getenv("HOME")` is your home**; cpp-repl's code sees the state
  directory's, where clang-repl's history goes.
- **A one-liner needs no server:** `echo 'code' | clang-repl` is as quick as
  the start-up table says; cpp-repl's answer, `--connect`, needs a server
  running.

The speed of the code once it runs is the same JIT's: the
[bench](../bench/README.md) found Eigen typed into cpp-repl with `-O3
--native` at 0.98–1.02 of clang++'s native speed from n = 32 to 3072 (64
GFLOP/s at n = 1024, clang-repl 23.1.2, 2026-10-14), and the README's probes
show `-O2` and `-march=native` reaching the JIT through `--Xcc` as through
cpp-repl's flags. There is no code-speed difference to measure.

## When to use which

Raw clang-repl: to see what clang does with one line, with nothing in the
way; to script the JIT where Python is unwelcome; for out-of-process or CUDA
work; and when working on clang-repl itself.

cpp-repl: for anything typed over more than one line; to look at values of
class type; for a session that must survive a crash or an exception, as a
session spent learning a library's API must; to run a program or a lesson
statement by statement, with its own stdin and exit status; for an agent's
loop, with `--json`, `--timeout` and a served session.

## Regenerating

```sh
make compare          # the host's clang-repl: compare/results/compare-N.json
make compare-docker   # inside cpp-repl:llvm23 and cpp-repl:llvm-snapshot
make compare-doc      # the tables above, from every compare/results/*.json
```

`compare/compare.py run` measures both sides with one clang-repl and writes
one JSON document; `render` rewrites the tables between the markers in this
file, the newest 23.x release in the main column and the other versions
where they differ. The images mount the checkout read-only, so `run` writes
to stdout. A hang costs its twenty seconds; a whole run takes a minute or
two.
